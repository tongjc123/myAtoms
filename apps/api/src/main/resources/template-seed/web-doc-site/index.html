快速开始

十分钟内把第一个反馈渠道接通，并在看板上看到第一条归类结果。这份文档假设你已经在用潮汐的团队版。

先看结论：三步就能跑通——创建工作区、接入一个渠道、确认归类规则。剩下的自动化可以等有真实数据后再调。

产品简介

潮汐把来自不同渠道的客户反馈收进同一个池子，按主题归并、按影响面排序，并把这些主题关联到具体的需求与版本上。它不替代客服系统，只负责回答一个问题：接下来最该修什么。

典型使用场景包括：

  • 应用商店评论与社群消息统一收集，避免"截图散落各处"
  • 销售和客服在同一个视图里看到客户原话与影响客户数
  • 版本上线后自动回信给提过相关反馈的客户

快速开始

1. 创建工作区

首次登录会引导你创建一个工作区。工作区是数据隔离的最小单位，成员、渠道和预算都挂在它下面。

2. 接入第一个渠道

在「渠道」页面选择来源并完成授权。以应用商店评论为例，只需要填写应用编号，历史评论会在 10 分钟内回填。

3. 确认归类规则

系统会给出初始规则集，建议先用一周真实数据再调整。规则支持按关键词、客户分层与渠道来源组合。

curl -X POST https://api.tide.dev/v1/channels \
  -H "Authorization: Bearer $TIDE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":"appstore","appId":"1234567890"}'
注意：密钥只在服务端保存，不要写进前端代码或提交到仓库。泄露后请立即在「设置 / 密钥」中轮换。

核心概念

概念说明示例
反馈 Feedback一条原始的用户输入，保留来源与原文fb_8f31
主题 Topic若干条相似反馈的归并结果tp_204
需求 Issue团队决定推进的具体改动is_77
版本 Release需求被交付的那次上线rl_19

接入渠道

目前支持邮件、工单系统、应用商店、社群机器人与 CSV 导入。所有渠道共享同一套字段规范，来源差异只体现在 source 字段上。

  • 邮件与工单：OAuth 授权后自动同步
  • 应用商店：按应用编号拉取，每天三次
  • 社群：机器人邀请进群后按关键词收集
  • CSV：适合一次性导入历史数据

Webhook 回调

当主题被创建、合并或状态变化时，潮汐会向你配置的地址发送 POST 请求。请求体为 JSON，签名放在 X-Tide-Signature 头里。

{
  "event": "topic.updated",
  "topic": { "id": "tp_204", "title": "导出时字段缺失", "feedbackCount": 37 },
  "occurredAt": "2027-02-11T10:24:31Z"
}

签名是请求体与密钥的 HMAC-SHA256，建议做时间窗校验，避免重放。

鉴权与密钥

所有接口使用 Bearer Token。Token 分为只读与读写两类，自动化脚本建议使用只读。

Authorization: Bearer $TIDE_TOKEN

反馈归类

归类分两步：先按规则命中，再由相似度合并。规则优先，避免模型把明显的问题分错。

需求与版本

主题可以直接转成需求，需求关联版本后会出现在发布看板上。版本发布时可以选择通知提过相关反馈的客户。

常见问题

历史数据能重新归类吗？

可以。修改规则后可以在「设置 / 归类」里选择重跑范围，重跑不会改变已有主题的人工合并结果。

支持多少条反馈？

单工作区默认保留 24 个月，超过后按月归档，仍可搜索但不再参与归类。
